# 梗库扩张工作流

目标：把有证据支持的新梗放进可搜索的梗库，并把可复现的数据提交 GitHub。

## 每批只走四步

1. **取素材**：选定一批未处理的视频，保存解说、画面和引用元数据。已有素材直接复用；不重复抓取。
2. **整理并复核**：按实际片段拆分梗，写定义和出处。冻结草稿后，另一次阅读原始证据复核；如实记录同一 Codex 模型的有限独立性。出处不明就留空，有疑点就隔离。
3. **人工审核后发布**：生成本批审核卡，展示梗名、解释、用法、关键源画面/片段的时间点、出处与疑点。交给 Vincent 选择通过、需要修改或暂不入库；可以整批通过，也可以只通过部分。只有明确通过且内容与证据仍一致的条目，才在本批一次发布前检查后用 `vault_loop.py publish --batch N` 入库。检查证据绑定、身份冲突和引用目标；这不是检索评测。
4. **核对并交付**：核对本批实际入库的条目、证据和修订，记录结果。小批照常入库；累计约 20–30 条已核对的新梗后，集中提交可移植记录和必要代码到 GitHub。默认累计至少 20 条，在小批结束时交付；候选耗尽或 Vincent 要求时提前交付剩余记录。不自动合并。

**发布到梗库**指写入应用数据库，页面和搜索可用。**推送 GitHub**指保存代码、梗记录和证据文本，供备份、协作和重建。两者分别记录完成状态。

## 阶段连续推进

每次接续任务时，完成当前阶段后继续处理已具备输入的下一阶段，不按小时把采集、解析、起草、复核和发布分开。草稿冻结后即可进行另一次证据阅读；复核必须依据原材料并单独记录结论，等待时间不增加同模型复核的独立性。

自动接续间隔改为 15 分钟，作为后台任务完成后接续和中断恢复的检查机会。若已有 worker 正在运行，只检查所有权与结果，不启动第二个任务；正常等待不生成报告。后台任务尚未完成、需要用户处理平台限制或存在具体未解决的证据问题时，才保留当前进度等待接续。

## Vincent 的入库审核

模型复核通过后，运行 `vault_loop.py human-review --batch N` 生成 `ai_context/batchN_human_review.md`，并展示给 Vincent。原始证据文字可展开，源视频可按时间点回看；准备卡片时补上与条目对应的关键源画面，不把整集接触表当作已挑选的关键证据。没有明确通过时，状态是 `awaiting_human`，不会公开入库；采集与整理其他素材可以继续。

确认来自 Vincent 在聊天中的实际回复。只为他明确通过的条目保存 `ai_context/human_approvals/<记录文件名去掉.yaml>.json`：`reviewer: Vincent`、`decision: approve`、`canonical_name`、审核卡上的 `fingerprint`、含时区的 `approved_at`、实际回复原文 `authorization`。禁止将模型复核、校验成功、沉默或过去的自动发布授权写成人工通过。核心解释、出处或证据变化后，旧确认失效，需要展示修改处并重新确认。需要修改或暂不入库的条目不生成通过记录。

批次发布和直接加载都检查上述确认绑定；没有确认的模型条目不会向应用提交证据或修订。已有公开记录不因此自动撤回，新发布或再次修订须经审核。人工通过说明 Vincent 同意这条解释入库，不代表所有历史出处已经独立查证。审核确认属于个人工作流，不提交 GitHub；数据交付仍只包含已审核并核对入库的条目。

优先复用本批已存的视频、OCR 和精确 ID 的解析结果。引用大小写、作者或内容不一致时不能用近似结果替代；不为了复用而全局更新旧素材。平台请求仍保持现有间隔，避免用加速请求换取限流风险。

## 检查按实际风险触发

| 改动 | 做什么 | 不做什么 |
| --- | --- | --- |
| 只新增梗记录与证据 | 人工式证据阅读、发布前校验、本批发布后核对 | 不跑后端、前端、Docker 全套测试；不新建重复测试 |
| 修改采集、复核或发布代码 | 跑能覆盖该改动风险的现有测试；必要时验证实际流程 | 不为了测试数量补镜像式测试，不在通过后反复重跑 |
| 修改检索、模型或评测代码 | 用相应现有回归测试；需要衡量效果时才做独立检索评测 | 不把检索召回当作事实正确率 |
| 提交代码 PR | 使用仓库正常代码 CI | 不要求日常扩张每批手动再跑同一套 CI |

取消按记录数量自动启动全库评测，以及“评测未结束就阻塞全部扩张”的默认规则。完整检索评测仅在 Vincent 要求或具体检索问题需要测量时启动；如启动，仍固定模型、配置、语料和金标准，使用可恢复检查点，不能混用不同快照。

新梗不必为评测额外生成查询。确实需要模型查询时，先读原材料写查询，再写定义，标注 model；已有人工查询保留原字节，单独统计。

## 保留必要的记录

每批一个输入清单、一次冻结复核和一个完成结果即可；任务 journal 用于防止重启后重复采集或发布。没有状态变化的巡检不制造新报告。`loop_state.txt` 只放当前状态和下一步，历史放日志。

原始证据、旧失败记录和完成的审计报告保留，但不再作为每轮必须阅读的待办。个人工作流、日志、检查点、凭据与原视频不进 GitHub。

## 常用命令

Windows 本地环境使用 `evals/run_vault.ps1` 执行 Python：

```powershell
./evals/run_vault.ps1 evals/vault_loop.py status --batch N
./evals/run_vault.ps1 evals/vault_loop.py publish --batch N --dry-run
./evals/run_vault.ps1 evals/vault_loop.py publish --batch N
```

一次只运行一个采集或发布任务。出现登录过期、验证码或 STOP 时保留进度并通知 Vincent；不绕过、不盲目重试。不启动付费 GPU，不使用 DeepSeek 或子代理。
