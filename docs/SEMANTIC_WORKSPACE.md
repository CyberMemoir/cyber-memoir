# 本地语义复核工作台

入口：`/review/semantic`，也可从审核工作台打开。运行 `make demo` 后访问 <http://127.0.0.1:3102/review/semantic>。页面只处理用户主动选择的文件；不读取业务库、不请求模型、不自动上传或发布。

## 使用

1. 导入 `citation_audit.py` 产生的未评级 JSONL 队列。完整原始字节 SHA-256 绑定后续复核文件；修改换行或断言也需视作不同输入。
2. 逐条阅读只读断言及保存证据，明确选择结论、填写声明归属和理由。没有预选“支持”。
3. 在一份保存原文中选择连续文字，点击“添加选中摘录”。鼠标／键盘选区转换为 Unicode 码点位置；emoji 不会按两个 UTF-16 单元保存。支持／部分支持／相反表述需要原文摘录。
4. 保存这条复核后，记录仍仅在本页内存；时间来自本机时钟。可显式撤回这一条本地评级，不改变原文件或文化记录。
5. 导出复核 JSON，并确认浏览器实际保存；重新导入相同队列后可加载此文件。导出不含证据全文，但可能含摘录、姓名及理由，仍应保留私有。
6. 用 [CLI 校验器](SEMANTIC_REVIEW.md) 对原队列与导出文件再做独立检查。浏览器接受 `YYYY-MM-DDTHH:mm:ss[.fraction]Z` 或 `±HH:mm` 的合法时区时间；CLI 可接受更宽的 ISO 表达，浏览器导出始终使用规范形式。

文件上限16 MiB；校验失败保留已有工作。切换断言、替换文件、站内链接与页面卸载对未保存／未导出状态提供确认；不会静默将半填记录导出为有效评级。没有 localStorage、自动备份或跨会话恢复。浏览器历史的 SPA 后退不保证触发卸载确认，操作前应导出；“发起下载”也不证明文件已经写入磁盘。

摘要与文字范围只证明绑定／字面对应，不证明证据真实或语义正确。署名和时间不认证身份或先后；这些记录不等于发布审批。五类结论独立保留，待复核不能算作完成。

## 本轮验证

- Python 独立生成合成断言身份，浏览器导出后由实际 `semantic_review.py validate` 校验；emoji 摘录 `[1,2)` 与 literal text 一致。重载、撤回、再次导出恢复 pending。
- 新4项浏览器回归覆盖完整流程／无API上传、错误摘要不替换状态、脏稿切换与文件替换确认、错误时间／额外字段／重复引用／Unicode边界／危险来源URL拒绝。
- 后端340通过、1集成跳过；Playwright66通过；Ruff与格式108文件、TypeScript、生产构建、契约无差异通过。初次全量浏览器启动碰到QA服务的同一构建目录锁，停止归属QA服务后重跑66项成功；不是忽略测试失败。
- 真实固定队列只做导入读取，**0 assessed、16 pending、上传0**；原19个gold／策展输入SHA不变。没有新增真实语义准确率或模型提速数据，不修改业务schema／数据／发布审批。
