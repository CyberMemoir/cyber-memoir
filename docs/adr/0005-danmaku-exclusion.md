# ADR 0005：V1 不收录弹幕

状态：提议。

## 背景

`ingestion/pipeline.py` 在挑选字幕轨时硬过滤 `x != "danmaku"`。B 站经 yt-dlp 输出时，
弹幕会作为一条「字幕轨」出现在 `subtitles` 中，因此不过滤就会被当成字幕入库。

这行过滤此前没有注释，也没有文档。它是一个决定，但看起来像疏漏——尤其对一个
以中文互联网文化记忆为目标、而弹幕正是中文互联网最有辨识度的文化形式之一的项目而言。
本 ADR 的目的主要是把这个决定写下来，以免半年后有人把它当 bug 修掉，或把它当共识引用。

## 决定

1. V1 继续排除弹幕，不进入 Evidence。
2. 理由不是弹幕缺乏价值，而是**弹幕不是它所在视频的转录**：
   - 弹幕是观众在时间轴上的评论。把它作为 `kind="subtitle"` 的 Evidence 入库，
     会让 `locator.start_ms` 指向「有人在此刻说了什么」，而不是「视频在此刻说了什么」。
     两者混入同一 chunk 池会污染检索：查一个梗的定义时命中的可能是观众的即兴发言。
   - 弹幕体量大、噪声高，按 chunk 计会迅速主导 BM25 与向量通道。
     检索的单 Source 候选限额（`retrieval_per_source_cap`）只是把问题挪到别处，并不解决它。
   - 弹幕作者是大量未署名的个人。ADR 0002 第 10 条只保留昵称与公开发布记录；
     批量入库弹幕会把大量个人发言固化进一个以「记住会消失的东西」为目的的库。
     这需要一次单独的隐私判断，不应作为字幕管线的副作用发生。
3. 明确记录：**弹幕是流传证据（evidence of circulation），不是被否决的材料**。
   它回答的不是「这个梗是什么意思」，而是「这个梗在什么时候、以什么密度被观众使用」，
   正是 V2 时间线所需要的信号，也是少数能反映扩散强度而非仅反映发布行为的一手材料。
4. V2 若引入，必须走独立路径，不复用 subtitle：
   - 独立的 Evidence kind，不与转录共用 `subtitle`；
   - 从检索投影中排除，或使用独立的 chunk 池，不与定义/用法材料竞争排序；
   - 以聚合形式入库（按时间分桶计数、去重后的高频文本），而非逐条保存；
   - 一次独立的隐私决定，并在届时的 ADR 中记录。
5. 人工补料路径不受此限。审核者可以把某条具体弹幕作为 `manual` 材料录入并说明定位，
   这是有人判断过的单条引用，与批量抓取是两回事。

## 代价

- 在弹幕是唯一文字线索的视频上（无字幕、无 ASR 结果），V1 会漏掉本可使用的材料。
- 「流传证据」这一类目前无处存放。在 V2 之前，时间线只能依赖人工录入的 Event，
  扩散强度无法度量。
- 排除是按 yt-dlp 的 `"danmaku"` 键做的。其它平台若以别的键暴露同类数据，不会被这条过滤拦住，
  需要在接入该平台时重新检查。
