# ADR 0004：检索分数下限与弃答

状态：提议。

## 背景

当前的弃答完全由断言可得性驱动。`rag/answer.py` 只在两种情况下不作答：
起源类查询没有 `origin` 断言，或没有任何已审核断言通过引用完整性检查。

代码里没有任何分数阈值。`search/retrieval.py` 融合后取前 N，重排器打完分只用于排序，分数随即丢弃。
因此存在这样一条路径：RRF 与重排器返回的全是弱匹配，而这些梗恰好带有已审核的 `definition` 断言，
系统就会基于错误的检索结果自信作答。此时引用是真的、证据是已审核的、断言是人写的，
唯独「这条断言与这个问题相关」这一步没有任何证据支撑。

这是代码尚未兑现「AI 不能无证据判断梗来源」的地方：证据链在检索环节断了一格，而其余每一格都锁得很紧。

## 决定

1. 新增设置 `answer_score_floor`，初值 0.35。低于该值的 chunk 不能支撑回答。
   取 0 表示完全关闭该阈值。
2. 阈值只能建立在重排器分数上。RRF 分数编码的是名次而非匹配质量——排第一的结果无论多差都得到
   `weight / (k + 1)`——因此 RRF 分数不可承载阈值。`FlagReranker` 以 `normalize=True` 调用，
   输出经 sigmoid 落在 (0, 1)，跨查询可比，是本管线中唯一经过校准的相关性信号。
3. 一个 Meme 的分数取其被检索到的 chunk 中的最高分。没有任何 chunk 过线的 Meme 不进入断言收集，
   落到既有的「目前没有足够的已审核证据回答这个问题」路径。
4. 精确匹配豁免。`exact_alias` 通道是归一化后的等值匹配（别名表、`platform_item_id`、`canonical_url`），
   属于同一性判定而非相关性打分，不适用相关性阈值。
5. 没有校准打分器时不静默放行。`reranker_backend=disabled` 或重排失败时，
   `/v1/search` 返回 `scores_calibrated: false`，`/v1/answers` 在 `degraded` 中记 `score_floor_unenforced`，
   并照常作答。默认部署（重排器关闭）的行为不变。
6. 检索端点不做过滤，只暴露分数：每个 match 带 `score`，每个 item 带 `retrieval_score`，
   结果带 `scores_calibrated`。呈现是检索接口的职责，弃答是回答接口的职责。
   人工在搜索页看到弱结果是有用的；把弱结果当作答依据不是。
7. 阈值是设置项而非常量。与本 ADR 一并 settings 化的融合常量
   （`rrf_k`、三路权重、`retrieval_channel_limit`、`retrieval_per_source_cap`、`retrieval_candidate_cap`）
   共同构成金标准评测集可扫的参数面。
8. 与 ADR 0002 第 7 条一致：`degraded` 含 `score_floor_unenforced` 的运行与开启重排的运行不可直接比较，
   评测记录必须保留该标记。
9. 0.35 是待标定的初值，不是实测结论。在金标准评测集跑出 `correct_abstention` 与 `recall_at_10`
   的权衡曲线之前，任何具体数值都只是占位。首次标定后在本 ADR 追加实测值与所用评测集版本。

## 考虑过但未采纳

- **证据级门槛**：要求断言所引的每条 Evidence 各自有过线的 chunk。这更严格，也更贴近「chunk 支撑回答」
  的字面含义，但会在检索正确、chunk 排名不均时误伤召回：一个梗被正确检索到，却因为定义所引的那条证据
  恰好排名靠后而被弃答。V1 先解决「检索到错误的梗」这一失效模式；证据级门槛留待金标准评测集
  能够度量其代价之后再提。
- **对 RRF 分数设阈值**：见第 2 条，不可行。任何看似有效的 RRF 阈值实际上只是在限制结果条数。
- **不设阈值，改为要求 LLM 判断相关性**：与 ADR 0001 第 6 条冲突。用一次生成来担保另一次生成的相关性，
  不构成证据。

## 代价

- 默认部署（`reranker_backend=disabled`）拿不到这层保护。这是显式降级而非隐式失效，
  但意味着不开重排器就没有分数下限，而开重排器需要本地模型资源。
- 阈值定高会压低召回，定低则形同虚设。在评测集标定之前，0.35 没有实证依据，
  不应被引用为「本系统的相关性阈值」。
- `exact_match` 豁免是一条绕过路径。别名表由审核写入，本身受审核约束，
  但一个过宽的别名会同时绕过阈值。别名审核的严格程度因此变得比以前更要紧。
- 多一个可调参数就多一条把评测集拟合过头的路径。ADR 0002 第 6 条的冻结要求同样适用于阈值扫参：
  为提升分数调阈值必须记录原因。
