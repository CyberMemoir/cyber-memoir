# ADR 0001：先锁定证据，再扩展生成能力

状态：接受。

1. 采用模块化单体，Web / API / Worker 分进程；不按业务模块拆微服务。
2. PostgreSQL 管结构化权威状态，S3 工件保存持久证据，搜索与向量为派生投影。
3. Revision 保存完整候选快照；父 Meme 的公开修订同时决定 Event、Relation、EvidenceLink 的可见性。
4. Evidence 本身不可原地改写；人工修订新增版本。撤回任一支撑证据时保守撤回相关条目，重新审核后才发布。
5. 不以 earliest collected / platform publish timestamp 直接推断 origin。
6. RAG 使用“已审核断言选择 + 确定性引用组装”，不依赖另一次生成模型自评来保证蕴含关系。
7. Job 合并小型 Outbox 与持久任务状态，Redis 为传递提示；允许重复执行，不承诺 exactly-once。
8. V1 统一使用 Evidence chunk 作为 BM25 / Vector 融合单位，梗描述加入检索投影，最后按 Meme 聚合。
9. 模型关闭/失败时明确降级；测试替身只存在于测试代码，不冒充生产推理。
10. 首期审核者采用部署令牌；多用户身份、细粒度授权、审核仲裁流程留到有真实协作需求后建设。

代价：审稿劳动更多；起源回答更保守；索引短时最终一致；单机资源限制影响大型模型并发。优先保住可追溯性，而非制造“无所不知”的体验。
