# 档案阅读与双向引用

本轮借鉴的是阅读与核查机制，不复制第三方品牌、图片或文化事实：

- [Know Your Meme 的条目导航](https://knowyourmeme.com/memes/this-is-fine)将含义、起源、传播和外部来源分开。本项目沿用含义—语境—起源—传播—关联—证据的阅读路径，保留星系与时间轴；未知出处不因增加一个章节而变成已确认事实。
- [维基百科的脚注机制](https://en.wikipedia.org/wiki/Help:Footnotes)把正文引用连到材料，并提供返回引用处的入口。本项目对定义、使用语境、起源断言、事件、关联和补充断言提供当前页编号与双向定位。

## 用户能做什么

1. 从档案阅读导航进入含义、语境、起源、传播、关联或证据。
2. 点击 `[1]` 等编号进入相应证据，焦点与当前引用标识随之移动；复制/新标签打开仍保留原生链接行为。
3. 在证据里按平台或包内原文/来源标题查找。正文引用指向被筛掉的材料时自动清除筛选，不制造空白跳转。
4. 从材料返回定义、语境、起源说法、事件或关联。浏览器前进/返回同步引用位置与键盘焦点。
5. 展开记录与工件的 SHA-256、下载当前公开工件，或复制带条目、修订和证据 ID 的引用链接。剪贴板失败如实显示，可直接复制原生链接。
6. 从回答引用进入对应档案中的材料，而不只跳到外部平台首页或原视频。

材料浏览器在桌面使用现有右栏并独立滚动，在手机回到正文后的单栏。文本与平台过滤只作用于当前条目公开材料，不是新的语义检索通道。

公开材料内还支持 [字面命中高亮、计数与逐处定位](EVIDENCE_FIND.md)：原文／标题／来源网址的当前筛选内前后浏览，不改写原文字节、历史引用或检索评分。

## 引用与版本

引用格式：

```text
/memes/<meme_id>?expected_revision=<published_revision>#evidence-<evidence_id>
```

`expected_revision` 是前端核对参数，**不是历史快照读取权限**。页面始终请求当前公开档案：

- 当前修订不同，提示链接记录的修订与当前修订，不冒充旧版本仍公开。
- 当前档案没有该证据，明确提示无法从缺失判断版本变动还是撤回；不另行读取未公开证据。
- 加载异步完成后再定位。更换条目时先清除旧内容并取消旧请求；不可用的新条目不会保留上一条档案。
- 编号只在当前公开页面内使用，分享链接使用证据 ID，不把易变的 `[1]` 当稳定标识。

回答接口增加 `claims[].meme_revision` 和 `citations[].meme_references`。同一材料可以支持不同条目、不同修订；后者只列实际被选择的断言上下文，不包括未选中候选。保留 `citations[].meme_revision` 兼容字段，含义改为第一条所选断言所属条目的修订；选择具体档案链接时应使用断言自身的 ID/修订或完整上下文列表。

## 事实边界

- 当前字段的支持引用必须匹配完整字段文本，不能用另一条不同定义的引用替代。相矛盾材料单独标识，不当作支持性确认。
- 起源未知、存在争议、支持材料未对应时有不同说明；已有记录的状态与引用不一致时不在界面声称已经确认。
- 新的 `supported` 起源审核必须同时有支持性 `origin` 引用和受支持的 `claimed_origin` 来源关系。只有反对材料或争议关系不能通过该状态的审核；本轮不自动修订历史记录。
- 带时区的事件时间格式化显式使用 `Asia/Shanghai`。传播事件的年/月精度不显示虚构的月日，秒级精度显示具体时刻；未知日期不补写。缺时区旧字段按保存日历显示并明确说明，不推定时区；起止范围与机器日期的处理见 [时间范围阅读](TIMELINE_RANGES.md)。平台发布时间与证据登记时间明确分开，不把登记时间叫作历史发生时间。
- 仅浏览当前公开证据与经审核断言。没有增加媒体镜像、下架探测、自动事实生成或公共历史修订接口。

## 复现

```sh
make contracts
make test
make check
cd apps/web && npx playwright test
```

新增后端回归覆盖同一证据关联两个条目不同修订、反对性起源材料与争议起源关系。新增浏览器验收覆盖字段/事件/关联双向引用、筛选恢复、历史导航、异步深链接、版本变化、缺失引用、复制失败、未知起源、支持状态不一致、回答上下文、不可用条目切换及年/月精度。所有材料均为明确标记的合成软件夹具，未写业务数据库、未改变人工查询字节。

2026-10-09 最终复核：后端全量 145 项通过、真实服务集成 1 项按环境跳过；浏览器全量 33 项通过；Ruff、TypeScript、Next.js production build、契约生成与差异格式检查通过。本轮没有测量真实描述查询召回、模型质量或实际平台素材效果。

全量复核还暴露了“材料刚保存，审核列表比 Worker 提取更早读取”的时序问题。新增受保护的 `GET /v1/reviews/queue`，先查询持久化材料任务状态，再读取待审稿；不把索引任务当作候选生成任务。工作台在材料任务待处理/执行中时每 2 秒检查队列，空闲时每 15 秒检查；不重叠请求，刷新不重置正在编辑的同一份草稿。更换令牌或离开页面会取消读取与定时器。空列表只说明目前没有候选，不再称所有任务已完成；失败记录也不被解释为公开证据失效。虚拟浏览器时钟的独立回归验证候选到达、编辑保留及令牌变化后的停止，真实临时 Worker 闭环随后通过。

## 视觉对照

设计依据是 `DESIGN.md` 和 GitHub main 的现有档案页面。为对照生成独立的只读代码快照，用相同合成材料渲染旧页与本轮页面，而不是用静态假界面作验收。内置 IAB 本轮不可用，因此使用 Playwright Chromium；通过 `view_image` 逐张检查 1505×1045 桌面参考态、实现态与 390×844 手机实现态，另有 320px 页面溢出验收。

| 对照点 | 结果与有意变化 |
| --- | --- |
| 文案与导航 | 品牌、原导航、条目名、别名和星图入口不变；新增声明的章节导航与引用操作，不新增营销眉题或虚构统计 |
| 布局 | 保留双栏与沟槽；新增起源阅读区，证据栏可独立滚动，手机仍为单栏 |
| 字体 | 复用衬线名称/标题、正文与小号控件层级；编号不再使用截短 UUID |
| 色彩与图标 | 保留夜空与薄荷色交互；支持/反对通过文字区分，不借用阶段色冒充事实强度 |
| 材料与容器 | 保留原文、定位和来源，仍使用细线列表而非卡片墙；技术摘要折叠，不压过阅读任务 |
| 交互与焦点 | 实际点击、复制、前进/返回和异步直达已验收；焦点可回到引用位置，无新标签行为劫持 |

首屏文案差异仅为本轮声明的阅读导航；其余新增信息均来自当前 DTO 或明确的缺失/版本说明。开发调试标记不属于品牌 UI。对照完成后的临时快照、截图和进程不作为交付保留。
