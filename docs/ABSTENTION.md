# 暂不回答：诊断原因与只读候选导航

参考 [Wikipedia 的消歧导航](https://en.wikipedia.org/wiki/Wikipedia:Disambiguation)：候选用于帮助读者浏览，不替读者认定正确主题。本库只借用这种交互原则，不复制页面/内容，不从模型记忆生成名称或把候选自动改写为新查询。

此前所有无断言回答都显示统一“缺少证据”，但已有公开结果、相关性不足、选择器空结果和公开状态变化不是同一回事。本轮添加兼容的结构化元数据：

| `abstention_reason` | 本次请求实际观察到的状态 |
|---|---|
| `no_public_matches` | 当前检索没有可用公开结果，不声称全网不存在或库中一定没有记录 |
| `low_relevance` | 有候选，但没有通过既有相关性下限，不把它们作为证据回答 |
| `no_approved_claims` | 通过资格/相关性候选中，没有可用于此次回答的核查断言 |
| `selection_empty` | 有可用核查断言，但选择器未选中足以回答的内容 |
| `corpus_changed` | 检索/候选复核期间可见性或公开修订变化，需要刷新 |

有证据断言时 reason 仍为空，正常断言/引用选择方式不改。不改 **0.35 下限**、模型分数、候选预算、原金标准或模型故障/忙碌协议；busy 仍是正式503，而不是弃答。此改进是说明与导航，不是修复六条正例弃答或证明原16条断言语义。

## 只读导航，不是证据建议

空断言回答最多附三个 `related_memories`，仅含当前已发布记录的 ID、名称、公开修订。没有定义、证据ID、起源、置信度或模型生成的解释。低相关性记录即使在候选中，也不能因此成为回答的 claim/citation。

- 名称来自重新读取的公开详情，不从生成模型输出取值。
- 返回前独立核对当前公开状态与修订。私有/撤回/合并/过期候选不出现在导航；变化时撤掉候选并说明刷新，不误导为缺来源。
- 链接带 `expected_revision`，但没有伪造的证据 anchor。之后版本变动由既有详情页版本冲突机制处理。
- 点击仅打开详情页，不自动以梗名重跑搜索、触发回答或利用精确别名豁免“提高召回”。
- 未匹配不造候选；旧 API 没有新字段时继续兼容，前端不会猜名字。

前端在原虚线弃答框中显示中文原因，以及“候选记忆仅供浏览，不是本次提问的证据回答”。继续保留检索结果、原输入与手动修改入口，不自动提交来源或生成文化断言。

## 验证与设计保真

- 新增8项后端回归包含低相关性/空公开结果/选择器未选/无核查断言、私有/撤回/修订变化独立复核和成功回答不混入候选。原下限回归改为检查明确原因及空 claims/citations，未删除下限约束。
- 4项浏览器回归包含只读版本链接/不重跑查询、旧接口兼容、手机长名称不溢出、URL无伪造证据 anchor，以及实际隔离 API 的空公开结果诊断。界面夹具均为合成验收，不当文化事实或真实模型效果证明。
- 没有本轮新增实模型指标，也不将“提供浏览链接”算作回答身份匹配或引用正确。相关字段已加入 OpenAPI/TS 契约。

小界面修正沿 `DESIGN.md`，不做 ImageGen 重设计。IAB 实际不可用，正常时钟 Playwright Chromium 在1505×1045桌面和390×844手机抓取改前/改后弃答状态，同次 `view_image` 核对四图：

| 对照项 | 结果 |
|---|---|
| 文案 | 首屏/导航/主操作不改；仅声明的弃答原因与“仅供浏览”文字/链接新增 |
| 布局 | 原虚线无证据回答框与双栏/手机纵向顺序保留；新增导航带来的高度增长是有意变化，不引入卡片墙 |
