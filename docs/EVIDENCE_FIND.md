# 证据内字面查找与定位

参考 [Firefox 页内查找](https://support.mozilla.org/en-US/kb/search-contents-current-page-text-or-links) 的命中高亮、次数与前后定位机制，适配已有公开档案的证据栏。只读取当前公开 DTO，不发起新的检索／回答／模型请求，不把文字命中当作断言支持程度。

## 阅读流程

运行 `make demo`，访问 <http://127.0.0.1:3102>，搜索“合成星灯”并进入条目。在“回到证据本身”的查找框输入原文、来源标题或网址的一部分：

- 沿用既有 NFKC／中文区域小写归一和首尾空格处理，做字面包含匹配；不改写查询为文化含义、不使用正则表达式、模型或模糊召回。
- 高亮当前可见证据的原文和来源标题。只有网址命中时，显示只读的来源网址及命中范围，避免“找到材料却看不到匹配文字”。
- 显示当前位置与可定位数量；上一处／下一处在当前筛选内绕回。查找框中 Enter／Shift+Enter 可前进／后退，不拦截浏览器 Ctrl+F，也不抢中文输入法确认键。
- 更改查找词、平台或清除筛选会重置当前命中；没有命中时定位控件禁用。按钮显式定位后聚焦标记，但不写 URL／历史或改变引用参数；引用跳转仍按原规则清除筛选并聚焦证据。
- 定位工具条在证据区域内吸顶，保留下一步操作。跳转的标记保留工具条高度的滚动余量，不被其遮住。

## 原文与边界

使用 [Intl.Segmenter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter) 划分原始字素，把归一化位置映射回完整原文范围。全角字母、组合重音、连字扩展和ZWJ emoji不会因匹配拆碎；同一原字素上的重叠命中合并为一处。希腊语上下文小写在完整字符串中计算，映射一致性不满足就不产生伪精确高亮。

`mark` 内仍是原文字串，所有前后片段逐字保留；没有 `dangerouslySetInnerHTML` 或DOM文本改写。看起来像HTML的材料仍只是文字。归一化命中不证明原文包含逐字相同的半角／小写输入，也不等于语义相同；这些UI范围不是语义复核工具的摘录或证据哈希。

渲染预算最多500个标记，超过时明确显示“仅高亮前500处”，当前数量不冒充全部次数。单字段超过200,000个UTF-16单元、缺少Segmenter或不能一致映射时只保留原有筛选和完整阅读并给出说明，不截断／改写证据。跨字段组合恰好匹配但无单字段可定位文字时也不制造标记。

没有新增上传、持久化、当前公开状态变动或文化审批；旧引用、版本核对、工件下载和返回引用位置保留。
