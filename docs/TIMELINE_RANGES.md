# 传播事件的起止范围与时间精度

参考 [TimelineJS 官方事件格式](https://github.com/NUKnightLab/TimelineJS3/blob/master/API.md) 将开始／结束作为独立字段、日期组件可按精度提供的做法。这里只适配当前公开档案的阅读，不安装TimelineJS、不复制品牌、不宣称兼容其JSON。官网格式页面本轮直接读取返回403，改查作者GitHub官方API文档。

## 展示

- 有已保存的结束时间时，显示“开始 至 结束”，不再丢掉 `occurred_at_end`。两端都只展示保存的年／月／日／秒精度；只有开始时间时不补结束，更不解释为“仍在持续”。
- 起止落在同一显示单位但实际字段不同，明确说明按保存精度展示，不展开更细日期。未知精度不因存在时间戳而显示精确日期；缺开始不从结束倒推。
- 不自动交换反向边界，不排序／改写原事件数组，不计算持续时长。反向范围、无效日历／偏移或未知精度明确待核对，保留原说明、时间依据和双向引用。单独的日期范围不能证明期间连续活动或全网首发。
- 使用 [HTML time 的有效机器日期格式](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/time)：年 `YYYY`、月 `YYYY-MM`、日 `YYYY-MM-DD`。不会把年／月转成虚构的一月一日／月初精确边界；无效／未知日期不输出机器值。
- 带时区字段按 `Asia/Shanghai` 显示；秒级机器值输出同一时刻的UTC形式、不超出秒精度。界面年份／月份／日期机器值取对应显示日历，而不是错误地取原UTC日。
- 上方TimeStrip仍是已有证据日期概览，不改为代表事件持续范围的区间图；有范围且实际绘制了该图时明确说明以下方起止标签为准。

## 实际发现的缺时区记录

实际临时SQLite演示 API 返回 `2026-01-01T00:00:00`，没有偏移。浏览器直接 `new Date(value)` 会按读者本地时区解释，不能据此声称已知统一时刻。本轮事件日期组件改为保留该字段的日历部分并明确“时区未记录；按保存的日历字段显示，不推定时区或实际时刻”。用于格式化的UTC框架只是稳定日历排版，不是补造UTC归属。

这类年／月／日机器值只表达保存的日历，秒级机器值保留无偏移的local datetime；不会追加猜测的Z或+08:00。混合有／无时区的两端不能核对实际先后；都缺时区时只检查保存日历字段是否反向。已有两个有时区边界的排序检查保留微秒尾部，不被JavaScript毫秒截断掩盖。

没有修改历史时间字段、业务库、审核状态或实际演示夹具。这个前端处理不能恢复SQLite过去可能丢失的偏移，也不覆盖平台发布时间／登记时间的所有其他格式化路径；后续应独立核查写入归一化和旧记录出处，不能给旧字段批量补时区。
