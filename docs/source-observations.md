# 来源观察快照

采集时追加一份「当时实际看到的数据」，供时间线与后续趋势研究使用。刷新来源不会覆盖旧快照；本次改动不补写过去的热度，不启动批量回访，不改变梗的人工审核与发布规则。

## 保存什么

- `observation_id`、UTC `observed_at`、准确的页面 URL、采集入口与 yt-dlp 版本。
- 页面返回的标题、描述、作者标识、发布时间和时长。发布时间与观察时间分开保存。
- 页面实际返回的播放、点赞、评论、转发、分享、收藏、作者关注者数量。平台不提供的字段为 `null`，真实零值为 `0`。
- `raw_metrics` 保留平台提供的简写数值；例如 `1.2万` 不会被换算成假精确整数。
- 请求结果为 `observed`、`fetch_failed` 或 `rate_limited`。失败计数为 `null`，不能据此认定删除、下架或热度为零。

只保存允许的字段，不保存 cookies、请求头、字幕下载地址、媒体格式列表或临时下载地址。页面 URL 去除查询参数与片段；当前 B 站和抖音的页面 ID 在路径中。依赖查询参数标识页面的其他网站，需要另行添加平台规则，不能直接据此归并身份。

观察快照不是起源证据，也不证明作者身份或传播关系。未来做预测时，只能使用预测时点以前已采集的快照；不能拿旧作品今天的计数冒充当年的热度。没有历史快照时保留缺失，采集今天的基线。

## 两条保存路径

后台每次来源元数据采集会写入 `source_observations` 表，按来源和观察时间可查询，完整允许字段保存在 `payload`；同时写入带 SHA-256 的存储文件。成功采集的快照先提交，后续材料处理失败也不丢失这次观察。原 `Source.metadata_key` 继续表示最新元数据，接口行为保持兼容。

本地 `prep.py` 的元数据探测以及新视频下载，写入输出目录的 `observations/<UUID>.json`。每次请求产生新文件，已有文件不能覆盖。下载产生的完整 `.info.json` 只有在快照成功保存后才删除；写入失败时保留原文件供恢复。复用旧视频或旧解析结果不会凭空生成一次新观察。观察目录与原 `.info.json` 默认不进 Git。

## 明确指定的小规模回访

使用项目的 Python 环境，例如：

```sh
python evals/feasibility/prep.py observe BV1xxxxxxxxx --out ./evals/feasibility
```

Vincent 的本地 Windows 工作区也可使用现有入口：

```powershell
./evals/run_vault.ps1 evals/feasibility/prep.py observe BV1xxxxxxxxx --out ./evals/feasibility
```

只请求元数据，不下载视频、不运行 OCR 或模型、不改 CSV、定义或人工审批。每次最多 10 个准确 URL/ID，默认间隔 20 秒且不能缩短；遇到失败或 412 就记录结果并停止，不自动重试。不支持的平台保留失败结果，不能声称已完成跨平台采集。

这只是保存和回访入口，尚未设置周期采样、搜索排名或候选抽样日志。未来添加采样任务时，要单独保存选择规则、搜索词及样本范围，避免只记录已经走红的梗。

## 启用后台

部署包含此改动的后台前，用现有迁移入口 `make migrate` 应用新增迁移 `d3e4f5a6b7c8`，随后启动新版服务。迁移只增加观察表和索引，已有来源不会被伪造历史观察。本地采集入口不依赖数据库迁移。

迁移回退会删除观察表；需要回退时先保留表数据与存储文件。这次实现没有替用户迁移运行中的数据库、部署服务或发起真实平台请求。
